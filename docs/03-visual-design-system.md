# UCI Website --- Visual Design System

**Project:** Iglesia UCI --- Unidad Cristiana de Intercesión\
**Document:** Visual Design System\
**Version:** 1.0\
**Status:** Approved design direction\
**Scope:** Public website and visual language shared with the CMS where
applicable

------------------------------------------------------------------------

## 1. Purpose

This document defines the visual language of the UCI website.

It establishes the visual rules that must guide:

-   Public pages
-   Homepage
-   Navigation
-   Typography
-   Color
-   Spacing
-   Buttons
-   Cards
-   Forms
-   Images
-   Icons
-   Sections
-   Content presentation
-   Responsive behavior
-   Motion
-   Empty and loading states
-   Accessibility-related visual decisions

This specification is based on the approved UCI visual identity, the
approved homepage concept, the generated desktop/mobile mockup, and the
visual direction established during the design phase.

The design must feel like a distinctive UCI experience rather than a
generic church website template.

------------------------------------------------------------------------

# 2. Design Direction

## 2.1 Core Character

The UCI website must communicate:

-   cinematic
-   modern
-   spiritual
-   sober
-   welcoming
-   human
-   premium
-   editorial
-   intentional
-   contemporary

The visual language should balance emotional spiritual imagery with
practical information.

The website should feel capable of presenting both:

-   a powerful worship or sermon moment
-   precise practical information such as service times and locations

Neither side should dominate the entire experience.

------------------------------------------------------------------------

## 2.2 Primary Visual Concept

The visual system is built around the relationship between:

**Globe + Bible + Heartbeat**

These elements represent the central visual language of UCI.

### Globe

Represents:

-   reach
-   people
-   community
-   mission
-   a church connected to a wider world

### Open Bible

Represents:

-   God's Word
-   biblical foundation
-   teaching
-   spiritual formation

### Heartbeat / ECG

Represents:

-   life
-   prayer
-   intercession
-   spiritual vitality
-   a church that remains active and connected

These elements should be treated as one visual identity system.

They should not be repeatedly used as unrelated decorative ornaments.

------------------------------------------------------------------------

# 3. Design Principles

## 3.1 Identity Before Decoration

Every major visual decision must reinforce the identity of UCI.

Decorative effects should not be introduced merely because they are
visually attractive.

------------------------------------------------------------------------

## 3.2 Cinematic but Functional

Dark cinematic compositions are a core part of the identity.

However, practical information must remain immediately readable.

Visual atmosphere must never reduce:

-   legibility
-   navigation clarity
-   accessibility
-   content discoverability
-   usability

------------------------------------------------------------------------

## 3.3 Real Human Experience

Real UCI photography should be preferred whenever suitable material
exists.

Priority should generally be:

1.  Authentic UCI photography
2.  Professionally produced UCI visual assets
3.  Carefully selected supporting photography
4.  Generated imagery only when appropriate and approved

The website must not become dependent on generic stock photography.

------------------------------------------------------------------------

## 3.4 Editorial Storytelling

Sections should feel connected.

The page should read visually as a story rather than as a collection of
independent cards.

The homepage rhythm should alternate between:

-   atmosphere
-   identity
-   practical information
-   community
-   teaching
-   participation
-   connection

------------------------------------------------------------------------

## 3.5 Controlled Contrast

The design intentionally alternates between:

-   near-black / navy cinematic sections
-   white / light information sections
-   blue transitional surfaces
-   restrained gold accents

This contrast creates rhythm and hierarchy.

------------------------------------------------------------------------

# 5. Color Usage Rules

## 5.1 General Ratio

The visual experience should generally be dominated by:

-   black
-   deep navy
-   white

with:

-   blue providing energy and atmosphere
-   gold providing controlled emphasis

Gold and blue should not compete equally for attention.

------------------------------------------------------------------------

## 5.2 Gold Hierarchy

Gold should communicate importance.

Recommended uses:

-   primary CTA
-   active navigation
-   key title accent
-   highlighted word
-   icon accent
-   decorative rule

Avoid using gold for every button or every heading.

------------------------------------------------------------------------

## 5.3 Gradients

Gradients may be used when they reinforce:

-   cinematic lighting
-   depth
-   image readability
-   transition between sections

Preferred direction:

-   black → navy
-   navy → transparent
-   blue → transparent
-   gold → transparent

Gradients should remain subtle and photographic.

Avoid generic neon gradients.

------------------------------------------------------------------------

# 6. Typography

## 6.1 Typography Character

Typography must combine:

-   contemporary sans-serif clarity
-   restrained editorial serif expression

The interface should primarily use a clean sans-serif.

Serif typography is reserved for:

-   major editorial headings
-   scripture
-   selected quotes
-   emotional storytelling sections

------------------------------------------------------------------------

## 6.2 Primary UI Typeface

Preferred direction:

**Inter** or a visually equivalent modern sans-serif.

Characteristics:

-   high readability
-   neutral forms
-   excellent digital rendering
-   strong numeric readability
-   broad weight range

Use the actual approved project font once finalized.

------------------------------------------------------------------------

## 6.3 Editorial Typeface

A refined serif may be used for:

-   hero display typography
-   selected sermon titles
-   scripture
-   testimony quotes
-   editorial headings

The serif must feel elegant and contemporary.

Avoid ornamental or excessively traditional church typography.

------------------------------------------------------------------------

## 7.1 Display Typography

Display headings should have:

-   strong contrast
-   controlled line length
-   generous line height
-   clear visual hierarchy

The hero may use mixed typography where one phrase is emphasized in
gold.

Example:

**UNA IGLESIA**\
**QUE INTERCEDE.**

The highlighted phrase should use gold or a restrained gold treatment.

------------------------------------------------------------------------

## 7.2 Uppercase Labels

Small uppercase labels are part of the visual language.

Examples:

-   `BIENVENIDO A UCI`
-   `SOMOS UCI`
-   `ÚLTIMO SERMÓN`
-   `PRÓXIMOS EVENTOS`

Characteristics:

-   uppercase
-   small size
-   increased letter spacing
-   strong contrast
-   restrained gold or blue accent where appropriate

------------------------------------------------------------------------

# 8. Spacing System

Use a consistent spacing scale.

Recommended base rhythm:

-   4px
-   8px
-   12px
-   16px
-   24px
-   32px
-   40px
-   48px
-   64px
-   80px
-   96px
-   120px
-   144px

Large editorial sections may use larger spacing where necessary.

------------------------------------------------------------------------

## 8.1 Section Spacing

Desktop:

-   typical section padding: 80--120px
-   major cinematic section padding: 96--144px

Mobile:

-   typical section padding: 56--80px
-   major sections: up to 96px when composition requires it

The page should not feel compressed.

------------------------------------------------------------------------

# 9. Layout System

## 9.1 Main Container

The public website should use a centered content container.

Target maximum width:

`1200px–1320px`

depending on the page and composition.

Full-bleed sections may extend to the viewport edges while their content
remains inside the main container.

------------------------------------------------------------------------

## 9.2 Grid

The design should use a flexible grid.

Typical desktop structures:

-   12-column conceptual grid
-   2-column editorial composition
-   3-column content grid
-   4-column content grid for compact archive cards

The grid should be adapted to the content rather than forcing every
section into identical cards.

------------------------------------------------------------------------

## 9.3 Full-Bleed Sections

The following may use full viewport width:

-   Hero
-   cinematic sermon sections
-   final CTA
-   major image sections
-   atmospheric transitions

Content remains aligned to the global container.

------------------------------------------------------------------------

# 10. Navigation

## 10.1 Desktop Navigation

The approved visual direction uses a transparent navigation layer over
the hero.

Structure:

-   UCI logo / icon at left
-   primary navigation centered or adjacent
-   action buttons at right

Primary navigation:

-   Inicio
-   Nosotros
-   Sermones
-   Eventos
-   Ministerios
-   Contacto

Primary actions:

-   Soy nuevo
-   Ver en vivo

------------------------------------------------------------------------

## 10.2 Initial Navigation State

Over the hero:

-   transparent or highly translucent dark background
-   white/light text
-   gold active indicator
-   subtle visual separation

------------------------------------------------------------------------

## 10.3 Scrolled Navigation

When the user scrolls:

-   navigation becomes more opaque
-   deep navy / near-black surface
-   subtle backdrop treatment
-   logo remains visible
-   text remains high contrast

The transition should be subtle.

------------------------------------------------------------------------

## 10.4 Mobile Navigation

Mobile navigation should prioritize:

1.  UCI logo
2.  Menu trigger
3.  Primary visitor action when space permits

The menu should open as a focused dark surface.

The mobile navigation should not become a dense list.

------------------------------------------------------------------------

# 25. Buttons

## 25.1 Primary Button

Characteristics:

-   gold background
-   dark text
-   medium/high contrast
-   rounded corners
-   compact horizontal padding
-   subtle hover illumination

Use for the most important action.

------------------------------------------------------------------------

## 25.2 Secondary Button

Characteristics:

-   transparent or dark background
-   white/light border
-   light text
-   subtle hover background

Use for secondary actions.

------------------------------------------------------------------------

## 25.3 Text Action

For low-priority navigation:

-   text
-   arrow/icon
-   no heavy container

Use where visual weight should remain low.

------------------------------------------------------------------------

## 25.4 Button Shape

Buttons should use a restrained radius.

Avoid:

-   extremely rounded pill buttons everywhere
-   excessive shadows
-   glossy effects
-   gradients that resemble generic AI-generated interfaces

------------------------------------------------------------------------

# 26. Cards

Cards are allowed but should not define the entire design.

Use cards primarily when they improve:

-   scanning
-   grouping
-   archive browsing
-   event discovery
-   CMS content management

Avoid turning every section into a grid of identical white boxes.

------------------------------------------------------------------------

# 27. Borders and Dividers

Preferred:

-   subtle white/gray borders on light surfaces
-   low-opacity blue borders on dark surfaces
-   gold only for selected or meaningful separators

Borders should be visually quiet.

------------------------------------------------------------------------

# 28. Shadows

Shadows should be subtle.

Preferred visual depth comes from:

-   lighting
-   gradients
-   image contrast
-   background separation

Avoid heavy floating-card shadows.

------------------------------------------------------------------------

# 29. Iconography

Use a consistent modern line-icon family.

Icons should be:

-   simple
-   clean
-   recognizable
-   lightweight

Use icons for:

-   calendar
-   location
-   arrow
-   play
-   navigation
-   contact
-   social networks

Icons should support content rather than become decorative
illustrations.

------------------------------------------------------------------------

-   navigation transition
-   subtle hover movement
-   section entrance
-   gentle glow

Avoid:

-   excessive parallax
-   constant floating animations
-   spinning decorative elements
-   aggressive zoom effects
-   animations that distract from content

------------------------------------------------------------------------

Possible:

-   slow background movement
-   subtle light movement

-   CTA hover

------------------------------------------------------------------------

-   slight image scale

# 34. Responsive Design

The design must be responsive by composition, not merely by shrinking
desktop elements.

------------------------------------------------------------------------

## 34.1 Desktop

Desktop layout may use:

-   full-width hero
-   multi-column grids
-   large typography
-   horizontal navigation
-   editorial two-column sections

------------------------------------------------------------------------

## 34.2 Tablet

Tablet should preserve:

-   visual hierarchy
-   navigation usability
-   image quality
-   section rhythm

Columns may collapse progressively.

------------------------------------------------------------------------

## 34.3 Mobile

The mobile experience must preserve the identity.

Priorities:

1.  readability
2.  service information
3.  CTA accessibility
4.  content hierarchy
5.  imagery
6.  visual atmosphere

The approved mockup demonstrates a compact mobile version of the same

------------------------------------------------------------------------

# 35. Mobile Hero

Mobile hero should:

-   remain visually immersive
-   reduce headline size
-   stack CTAs
-   preserve service information
-   keep the subject of the image visible
-   prevent text from covering important faces or focal points

The hero should not simply crop the desktop composition arbitrarily.

------------------------------------------------------------------------

# 36. Mobile Content

Three-column sections should generally become:

-   single column
-   or horizontally scrollable where justified

Sermon cards and events must remain easy to browse with touch.

------------------------------------------------------------------------

# 37. Accessibility

Visual design must maintain:

-   sufficient contrast
-   visible focus states
-   readable text sizes
-   clear interactive states
-   non-color-only status communication
-   meaningful image alternatives
-   reduced-motion support

Gold text should not be used on light backgrounds where contrast becomes
insufficient.

------------------------------------------------------------------------

# 38. States

Interactive components should define visual states for:

-   default
-   hover
-   focus
-   active
-   disabled
-   loading
-   error
-   empty

States must remain visually consistent across the website.

------------------------------------------------------------------------

# 39. Empty States

Empty states should be informative and calm.

Examples:

No upcoming events:

> No hay eventos próximos.

No sermons for a filter:

> No encontramos sermones con estos criterios.

Avoid decorative empty states that add no useful information.

------------------------------------------------------------------------

# 40. Loading States

Loading states should preserve the visual hierarchy.

Use:

-   subtle skeletons
-   restrained opacity
-   gentle transitions

Avoid large spinners when content skeletons can communicate structure.

------------------------------------------------------------------------

# 41. Error States

Errors must be:

-   clear
-   concise
-   actionable
-   non-technical for public visitors

Example:

> No pudimos cargar este contenido. Intenta nuevamente.

Administrative errors may expose more detailed information to authorized
users when appropriate.

------------------------------------------------------------------------

# 42. Content Density

The public website should avoid excessive information density.

Important content should have breathing room.

The homepage should feel spacious even when it contains substantial
content.

------------------------------------------------------------------------

# 44. Design Anti-Patterns

The following should be avoided unless explicitly justified:

-   generic church templates
-   excessive white cards
-   excessive rounded corners
-   excessive gold
-   excessive blue
-   random gradients
-   generic stock worship imagery
-   cartoon religious illustrations
-   floating crosses as decoration
-   generic doves
-   excessive celestial backgrounds
-   excessive particle effects
-   excessive glassmorphism
-   oversized shadows
-   visual clutter
-   dense dashboards on the public site
-   excessive animations
-   inconsistent icon styles
-   decorative elements without semantic purpose

------------------------------------------------------------------------

# 45. CMS Visual Relationship

The CMS belongs to the same product but does not need to replicate the
cinematic public website literally.

The public website prioritizes:

-   emotion
-   identity
-   storytelling
-   visitor experience

The CMS prioritizes:

-   clarity
-   efficiency
-   content management
-   operational visibility

The CMS may use the UCI color palette and typography while adopting a
more functional interface structure.

# 46. Design Consistency Rules

All new pages and components must maintain:

-   the approved color palette
-   typography hierarchy
-   spacing rhythm
-   button hierarchy
-   icon consistency
-   image treatment
-   dark/light section rhythm
-   UCI brand identity

A new component should not introduce an unrelated visual language.

------------------------------------------------------------------------

# 47. Visual Priorities

When visual decisions conflict, prioritize:

1.  Content readability
2.  UCI identity
3.  Visitor comprehension
4.  Accessibility
5.  Visual hierarchy
6.  Emotional atmosphere
7.  Decorative detail

# 48. Reference to Approved Mockup

The generated UCI homepage mockup is the primary visual reference for
the initial composition.

It establishes:

-   desktop/mobile relationship
-   navigation treatment
-   hero composition
-   typography direction
-   dark/light rhythm
-   section order
-   image treatment
-   card treatment
-   CTA hierarchy
-   sermon presentation
-   event presentation
-   ministry presentation
-   testimonial presentation
-   final CTA
-   footer treatment

The mockup is a visual reference, not a pixel-perfect implementation
contract.

Content, spacing and component dimensions may adapt to real content and
responsive requirements while preserving the approved visual language.

# 49. Design Tokens --- Conceptual Reference

The implementation should expose the visual system through centralized
tokens rather than scattered values.

Conceptual groups:

``` text
colors
typography
spacing
radii
borders
shadows
breakpoints
motion
container
z-index
```

The final implementation may refine token names and exact values without
changing the approved visual direction.

through:

-   community
