# Prisma — schema & migrations (Phase 1)

Canonical persistence layer for the UCI Node API.

## Why `prisma/` (repo root) instead of `src/db/`

Prisma's CLI expects `prisma/schema.prisma` and `prisma/migrations/` by
convention. Keeping them at the repo root means `prisma migrate`, `generate`
and `studio` work with zero configuration, and the schema stays adjacent to its
versioned migrations. `src/db/` (the Phase 0 skeleton) remains for future
domain notes and seed data, but the schema and migrations live here
(docs/02 §33).

## Conventions (docs/02 §31–33, docs/08 §34–36)

- **IDs** — `String @id @default(uuid())`. UUIDs are generated by the API,
  never by clients (docs/08 §34).
- **Naming** — DB objects are `snake_case`; Prisma model/field names are
  `camelCase`, mapped explicitly with `@map` / `@@map` so the physical schema
  never depends on Prisma's casing.
- **Timestamps** — every table has `created_at` and, unless append-only,
  `updated_at`. Content tables add `published_at` / `unpublished_at`;
  auditable content adds `created_by` / `updated_by` (nullable FK → `users`).
- **Append-only exceptions** — `Session` (revoked via `revoked_at`),
  `SermonRevision` (immutable snapshots), `AuditLog` (immutable trail) and
  `MediaReference` (a usage link between a media asset and a content entity;
  created once, removed via FK cascade) have no `updated_at`.
- **Join tables** — `user_roles` and `role_permissions` carry no timestamps;
  they are pure association rows with a composite primary key (conventional).
- **Content lifecycle** — the `ContentStatus` enum mirrors
  `src/shared/types.ts` (single source of truth); keep them in sync
  (docs/08 §48, §57).
- **Relational constraints** — join tables (`user_roles`, `role_permissions`)
  cascade on delete; audit FKs (`created_by`/`updated_by`/`actor_id`) are
  `SetNull`; `media_references.media_asset_id` is `Restrict` so a referenced
  asset cannot be deleted (docs/08 §37).

## Workflow

```sh
pnpm prisma:generate   # regenerate the typed client after schema changes
pnpm prisma:migrate    # create/apply a dev migration (prisma migrate dev)
pnpm prisma:studio     # open Prisma Studio
pnpm db:push           # push schema without a migration (prototyping only)
```

Requires `DATABASE_URL` in `.env` (see `.env.example`). Never commit `.env`.

## Boundaries (docs/07 §59)

The frontends (Astro web / React admin) never import Prisma or connect to
PostgreSQL directly. `@prisma/client` is only consumed by `src/server/db.ts`.
